# 振り返り（スキル確認）

## 師匠の宣言（原文 2026-10-23）

> 振り返りはスキル確認だけにしよう、元のルールを変更して恒久的にスキル確認だけやろう

**振り返り＝スキル確認だけ。** ビジョンの問いかけ・合意ドキュメントの変更回数の集計・教訓の作文はしない
（confirmed Skill `retrospective-is-mainly-skill-extraction`）。

## トリガー

以下のタイミングで「スキルの確認をしますか？」と問いかける:  
- スプリント完了時  
- 大きなコミット時  
- マイルストーン到達時

## 先送り

師匠が「後で」「XXまで終わってから」と言った場合:  
条件を記憶し、満たされたタイミングで再度問いかける。

## 手順

### 1. 候補を集める

材料はこのスプリントで起きたこと:

- CorrectionRecord（`~/.claude/pair-agent/corrections/`）
- 師匠の宣言・判断（合意ドキュメントの原文）
- 差し戻し・⚠ AI 判断・実測で分かったこと（ジャーナル）

候補を出す前に、ペア固有（`~/.claude/pair-agent/skills/`）とプロジェクト固有（`.pair-agent/skills/`）の Skill を検索する。
重なるものは**既存の Skill の更新**として出す（重複を作らない）。

### 2. 候補を出す

今回のスプリントから Skill にするものの候補です。

■ 新規  
 {n}. [{category}/{maturity 案}] 「{内容}」  
 根拠: {根拠}  
 保存先: {ペア固有 or プロジェクト固有}

■ 既存の更新・昇格  
 {n}. [{skill_id}・{current} → {proposed}?] 「{足す内容}」  
 根拠: {根拠}

承認・却下・修正を教えてください。

候補が無ければ「今回は Skill にする候補はありません」と言って閉じる。

### 3. 師匠の判断を反映する

- 承認 → Skill ファイルを作成／更新（confirmed）
- 却下 → 作らない
- 修正 → 内容を直して保存
- 済んだらスプリントを completed にする

## しないこと

- ビジョンの問いかけ（師匠が自分から述べたときだけ `~/.claude/pair-agent/vision/` に記録する）
- 合意ドキュメントの変更回数の集計・原因の考察・教訓の作文
