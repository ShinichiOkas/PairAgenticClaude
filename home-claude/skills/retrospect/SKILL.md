# 振り返り（スキル確認）

## 師匠の宣言（原文 2026-10-23）

> 振り返りはスキル確認だけにしよう、元のルールを変更して恒久的にスキル確認だけやろう

**振り返り＝スキル確認だけ。** ビジョンの問いかけ・合意ドキュメントの変更回数の集計・教訓の作文はしない
（confirmed Skill `retrospective-is-mainly-skill-extraction`）。

## 師匠の宣言（原文 2026-10-27）— 振り返りを自動にする

> スキルの振り返りも自動にして、ユーザーの応答待ちは悪！

**振り返りは自動で走る。「スキルの確認をしますか？」と問いかけない。応答を待たない。**
Skill を登録・更新して、何を登録したかを事後に報告する。師匠は事後に取り消せる。

## トリガー

以下のタイミングで**自動で**走らせる（問いかけない）:  
- スプリントを閉じるとき  
- マイルストーン到達時  
- 大きなコミット時（候補があれば）

## 先送り

師匠が「後で」「XXまで終わってから」と言った場合だけ、条件を記憶し、満たされたタイミングで走らせる（走らせるときも問いかけない）。

## 手順

### 1. 候補を集める

材料はこのスプリントで起きたこと:

- CorrectionRecord（`~/.claude/pair-agent/corrections/`）
- 師匠の宣言・判断（合意ドキュメントの原文）
- 差し戻し・⚠ AI 判断・実測で分かったこと（ジャーナル）

候補を出す前に、ペア固有（`~/.claude/pair-agent/skills/`）とプロジェクト固有（`.pair-agent/skills/`）の Skill を検索する。
重なるものは**既存の Skill の更新**として出す（重複を作らない）。

### 2. 自動で登録・更新する

候補ごとに maturity を決めて、その場で Skill ファイルを作成／更新する（承認待ちにしない）:

- **師匠の原文の宣言・叱責に裏付けられた候補 → confirmed**（`confirmed_by: human`、根拠に原文を引く）
- **AI の観測だけの候補 → forming**（`proposed_by: ai`。`confirmed_by` は null）
- 既存 Skill と重なるものは、既存の更新として足す（重複を作らない）

### 3. 事後に報告する（問いかけない）

今回のスプリントで登録・更新した Skill です。

■ 新規  
 {n}. [{category}/{maturity}] 「{内容}」  
 根拠: {根拠}  
 保存先: {ペア固有 or プロジェクト固有}

■ 既存の更新・昇格  
 {n}. [{skill_id}・{current} → {new}] 「{足した内容}」  
 根拠: {根拠}

取り消したいものがあれば言ってください（言われたら Skill を取り消し、必要なら CorrectionRecord に記録する）。

候補が無ければ「今回は Skill にする候補はありません」と 1 行で報告して閉じる。報告は短く 1 回。返事は待たない。

- 済んだらスプリントを completed にする（師匠の返事を待たない）
- 師匠が事後に取り消す・直す → その場で Skill を取り消す／修正する（forming のものは、師匠が内容を認めた時点で confirmed に上げる）

## しないこと

- ビジョンの問いかけ（師匠が自分から述べたときだけ `~/.claude/pair-agent/vision/` に記録する）
- 合意ドキュメントの変更回数の集計・原因の考察・教訓の作文
