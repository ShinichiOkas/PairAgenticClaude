# スプリントライフサイクル管理

## 状態遷移

協議(deliberating) → 合意(agreed) → 実行(executing) → 振り返り(retrospecting) → 完了(completed)

差し戻しは実行中にいつでも可能（協議に戻る）。

## スプリント開始

**現在地は作業ツリーごと**（2026-09-21〜。旧・単一 `.pair-agent/current-sprint.json` は廃止・道標のみ。
詳細は対象プロジェクトの `CLAUDE.md`「スプリントの現在地は作業ツリーごと」を見る）。

### 旧形式からの移設（初回セッションで行う）

`.pair-agent/current-sprint.json` が**あり**、`.pair-agent/current/` が**無い**プロジェクトでは、
新方式へまだ移設されていない。セッション開始時にそのプロジェクトへ最初に触れる回で移設する:

0. 写す前に確かめる: 旧ファイルの `sprint_id` のジャーナルが `.pair-agent/sprints/` に**既にあるか**、
   `.pair-agent/agreements/` の**最新の合意がどれか**（status と日付）を見る。旧ファイルが閉じた
   スプリント（ジャーナルや合意が completed）を指していたら**写さない**（閉じた記録を古い中身で
   上書きしてしまう）。そのときは師匠に、ポインタをどのスプリントに向けるかを聞き、手順 2 へ進む
   （由来: ray 2026-10-26。旧ポインタが閉じた repl-log を executing のまま指していて、手順 1 のとおり
   写すと `sprints/repl-log-20261021.json` を壊すところだった。師匠承認「候補は全部承認。」）
1. `.pair-agent/current-sprint.json` の中身（経過含む）を丸ごと
   `.pair-agent/sprints/<sprint_id>.json` へ写す（`sprint_id` が無ければゴールから採番する）
2. 作業ツリーの鍵を計算し（下記コマンド）、`.pair-agent/current/<鍵>-<末尾ディレクトリ名>.json` を
   ポインタとして新規作成する（`journal` に手順 1 のファイル、手順 0 で写さなかったときは
   師匠が選んだスプリントのジャーナルを指す）
3. `.pair-agent/current-sprint.json` を道標に置き換える:
```json
{
  "_moved": "現在地は .pair-agent/current/<鍵>.json（作業ツリーごと）、経過は .pair-agent/sprints/<sprint_id>.json。CLAUDE.md『スプリントの現在地は作業ツリーごと』を読むこと",
  "status": "moved"
}
```
4. 以降は下記の通常手順に従う

師匠がゴールを伝えたら:

1. 作業ツリーの鍵を計算する（`ホスト名 + git rev-parse --show-toplevel` の SHA-1 先頭 8 桁）
2. `.pair-agent/sprints/<sprint_id>.json` を新規作成し、経過（`経過` 配列）を書く先とする:
```json
{
  "sprint_id": "<uuid>",
  "status": "deliberating",
  "goal": "<ゴール>",
  "created_at": "<timestamp>",
  "agreement_path": ".pair-agent/agreements/<goal-slug>.md"
}
```
3. `.pair-agent/current/<鍵>-<末尾ディレクトリ名>.json` をポインタとして作成（無ければ新規、あれば上書き）:
```json
{
  "workcopy": { "host": "<host>", "path": "<top>", "key": "<鍵>" },
  "sprint_id": "<uuid>",
  "status": "deliberating",
  "journal": ".pair-agent/sprints/<sprint_id>.json",
  "updated_at": "<timestamp>"
}
```
4. 合意ドキュメントの起草を開始（/agreement-document を使用）

## **協議フェーズ**

`~/.claude/pair-agent/skills/` と `.pair-agent/skills/` からSkillを検索し協議深度を決定する:

* skip / light（**既定**）: 信頼して進む、または推奨を 1 行示して着手する  
* thorough: 師匠が「詰めよう」と言ったとき、または破壊的・不可逆・外部影響のときだけ  

協議は 1 画面で足りる大きさにする。聞くのは師匠にしか決められない方針だけ（各 推奨つき・最大 3 問）。答えを待たずに進められる作業は進める（2026-10-27 改め: 師匠の宣言『とにかく速度！回転！不停止！』『ユーザーの応答待ちは悪！』）

師匠の選択肢:

* 懸念を受け入れてドキュメントを更新する  
* 見切り発車を宣言する（懸念をドキュメントに残して実行へ）

## **合意→実行**

師匠が「これでいこう」「OK」「始めて」等と言ったとき、または要求が明確で推奨が決まっているとき（言われなくても進める。おまかせは常にこれ）:

1. ジャーナル（`.pair-agent/sprints/<sprint_id>.json`・正）とポインタ（`.pair-agent/current/<鍵>-*.json`）
   両方の status を “executing” に更新
2. 合意ドキュメントの status を “executing” に更新  
3. 実行を開始

## **実行フェーズ**

* 合意ドキュメントのスコープ内で自律実行する  
* スコープはファイルパスで事前定義しない。タスク記述から判断する  
* 判断が難しい変更は、推奨を決めて進め、判断を終わりの報告にまとめる（師匠にしか決められない方針・設計の判断、破壊的操作、外部送信だけ止まって問う）。確かめ（実機・API・GUI）は自分で通し、師匠の確認・目視を待たない（2026-10-27 改め: 師匠の宣言『エージェントは代行しないならエージェントじゃない』ほか）  
* 「勝手なことするな」と言われたら即停止し、合意ドキュメントに追記する

### **差し戻し（人間・AIどちらも可）**

* 前提崩壊: 実装してみたら前提が間違っていた  
* より良い方法: 合意範囲を変えると全体最適になる

差し戻し後: ジャーナルとポインタ両方の status を “deliberating” に戻す。

### **常に sync（実行中ずっと）**

* 作業の区切りごとにコミットして push する。作業の前には pull する。差分を溜めない（師匠の宣言 2026-10-27『並行で作業できるように常にコミット、プッシュ！常にpull！差分を許すな、常にシンクが正義！』）  
* 品質は「バグを出さないより、出して秒で直す」。確かめは自動で通し、壊れたらすぐ直して次の区切りへ進む。念入りな事前工程を積まない  
* 判断したなら最後まで責任をもってやり切る（途中で師匠へ投げ返さない）  
* **不具合を見つけたら即バグ票。** 書くのは見たことだけ（症状・実測・証拠・再現手順）。**調査はしない**（調査と診断は直す役の仕事）。票を書いたら**すぐ並列で直す役を起こす**（師匠の宣言 2026-10-27『不具合を見つけたら即バグ票！…バグ票を作ったらすぐ並列で直させろ！』）  
* **今やることに集中し、脱線しない。** 見つけた課題は無視せず、票にして誰か（直す役）に託す  
* **揺れるテストは即直す。** 不安定なテストは無価値。「自分の変更の影響ではない」と言って逃げない  
* **「Not my business」は禁句。** 全員で全部やる。アサイメントは免罪符ではない。範囲外のものも流さず、票にして託す。自分の範囲ですぐ直せるものはその場で直す  

## **完了→振り返り**

タスク完了時:

1. `.pair-agent/sprints/<sprint_id>.json`（ジャーナル。正）と `.pair-agent/current/<鍵>-*.json`
   （ポインタ）両方の status を “retrospecting” に更新
2. 振り返り（＝スキル確認だけ。`retrospect` スキル・師匠の宣言 2026-10-23）を**問いかけずに自動で実行**し、登録した Skill を事後に報告する（師匠の宣言 2026-10-27「スキルの振り返りも自動にして、ユーザーの応答待ちは悪！」。師匠の原文の宣言に裏付けられたものは confirmed、AI の観測だけのものは forming）  
3. 応答を待たず、そのまま完了へ進む（師匠は事後に取り消せる）

振り返り完了後:

1. ジャーナルとポインタ両方の status を “completed” に更新（食い違ったらジャーナルを正とし
   ポインタを直す）。経過はすでに `.pair-agent/sprints/<sprint_id>.json` に書かれているので、
   改めて保存する操作は無い
2. 次のスプリントが始まるまでポインタは completed の sprint_id を指したまま残ってよい
   （D-3: 次の開始時にポインタの `journal` を新しいジャーナルへ書き換える）
