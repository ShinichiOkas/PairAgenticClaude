**設計の対象にはすべて ID を振る。一度振った ID は変えず、解決・却下・廃止しても欠番のまま残し、再利用しない。**

## なぜこの体系で要るか

ID は議事録・アプローチドキュメント・状態の定義式から参照される。**番号を詰めた瞬間に、過去の議事録が別のものを指すようになる**（§19.2）。
システム状態は ID の式で書く（SS-03 ≡ CS-LC01-03 ∧ CS-LC02-02 ∧ CS-LC03-02）ので、ID が安定しないと定義そのものが壊れる（→ 状態の三段導出）。
因果の鎖・要再確認の印・判例の参照も、すべて ID の参照で成り立つ（→ 上流変更の仕分け、→ 判例の照合）。

接頭辞（10-method §3.7）：
- 2〜3 文字-連番：アクター AC・ユースケース UC・論理コンポーネント LC・関連 RL・要求 RQ・関心事 CN・ステークホルダ SH・品質特性シナリオ（区間）QS・状態 WS／SS／CS・課題 IS・リスク RK・アプローチドキュメント AAD・イノベーション候補 IC・ダビンチノート DN・設計ノート NT・ビュー VW …
- 1 文字＋連番（版や構成を指すもの）：決定点 D・案 D〈n〉-A・構成 K・スナップショット S・発行 P

## How to apply

- **接頭辞で種別が分かるようにする。** 利用者が足す要素の型は、定義するときに接頭辞も決める
- **却下・廃止は状態で表す。** 削除しない。番号も残す
- **案の番号は決定点の番号の下につける**（D〈n〉-A）。案が増えても既存の番号は動かない
- **コンポーネント状態は名前に引っ張られない形にする**：`CS-〈LC の ID〉-連番`。名前は併記する
- ⚠ **優先度順の並べ替え・文書の整形・ファイルの分割で、連番を振り直さない**（MD-076）
