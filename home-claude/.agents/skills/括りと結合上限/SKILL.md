**分割するほど要素の中は単純になるが、要素間の結合が増える。結合は括りでまとめ、括りごとの外部結合に上限を置いて抑える。数えた結合数は案を比べる材料にし、課題の種別にはしない。**

## なぜこの体系で要るか

要素が単純になるのは、他の要素との関連が簡単化されるから。**関連が簡単化されない分割は複雑度を下げない。** 分割数を増やし続けると、全体の複雑度は分割しない場合と同じになる（§8.4）。
要素数 n の結合の最大数は Sn = ((n−1) + (n−1)²) / 2（＝ n(n−1)/2）。本文は「指数的に増大」と書くが、式は n の**二次**であり、同じ節の後半も「二次曲線」と書いている。
§8.4 の図（数値は画像のみ）: 100 要素を n 個の括りに分けると、内部の要素数と括りの数が 10:10 のとき内外合計の結合数が最小。外部結合を 5 に制限すると、外部接続数の増加が二次曲線から直線になる。

## How to apply

- **案ごとに 3 つを数えて並べる**: 要素の数／要素間の結合の数／外部との結合の数（§8.5）
- **括り方の候補は、括りの数がおよそ √n になるものから出す**
- **括り（コンポーネント・モジュール）を定義するとき、他の要素との接続数の上限を決める**
- **「分解しない」案も同じ表に載せる**（→ 分解しない選択）
- ⚠ **数字が大きいこと自体を課題にしない。** 指標を検出規則にすると数合わせの設計が生まれる。手法は「複雑度超過」のような課題の種別を作らない（MD-101）
