**「速い」「安全」を、測れる量と閾値と測定条件の 3 点に落とす。**
落とせないものは、後から誰も合否を出せない。

## なぜこの体系で要るか

`アーキテクチャ` の事後条件は「仕様の各品質要求に対応する構造上の手当てがある」。
**手当てがあるかを確かめるには、まず要求が測れる形でなければならない。**

## How to apply

- **シナリオの形にする** —— 刺激 / 発生源 / 環境 / 対象 / 応答 / 応答尺度
- **測定条件を書く。** 「1 秒以内」は条件が無いと意味を持たない
- **閾値の出どころを書く。** 業務要件か、環境上限か、暫定か（→ 扱いの型の使い分け）
- ⚠ **測れない品質特性は、測れないと書いて上げる。** 言い換えて誤魔化さない
