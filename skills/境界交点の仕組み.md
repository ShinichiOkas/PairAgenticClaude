**システムバウンダリーと、アクターの線・依存の矢印との交点には、必ず何らかの仕組み（UI・状態の検知・受け渡し）が要る。交点を 1 つずつ数えて、仕組みを定義する。**
交点に仕組みが無いと、前提が満たされないまま動き始める事故が起きる。

## なぜこの体系で要るか

境界を引いた時点で「境界を越える接点」が決まる。**接点の定義漏れが、のちの仕様漏れ・事故になる。**
教科書は「バウンダリー交点に仕様が宿る」と言う（§18.3）。交点を数えることが、仕様の抜けの点検になる。

炊飯器の例（§11.4）:

| 場所 | 必要なもの |
|---|---|
| 料理人 ─ ご飯を炊く（操作の線） | 操作のための UI 定義 |
| 米を準備する ─ ご飯を炊く（依存の矢印） | 米の準備完了の状態定義と検知方法、準備された米の投入方法の定義 |
| ご飯を炊く ─ 後処理をする | 炊き終わった後にすべきことと方法の定義（まだシナリオの詰めが甘い） |

依存の矢印との交点に検知の仕組みが無いと、**米が準備できていないのに炊き始めてしまう。**

## How to apply

- **境界線と交わる線・矢印を全部数える**
- **操作の線 → UI を定義する。依存の矢印 → 前提の状態の定義と検知、受け渡しの方法を定義する**
- **後工程側の線も数える。** 詰めが甘い箇所は「詰めが甘い」と書く
- **交点ごとの仕組みはインタフェースの候補として渡す**（→ インタフェース設計）
- ⚠ **交点の仕組みが定義できないなら、その境界はまだ決まっていない**（→ システムバウンダリーの決定に戻る）
