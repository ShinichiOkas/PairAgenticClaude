## 根（症状ではなく）

当初は「昇格ゲート欠如」「固有名漏出」を症状として捉えた。対話で根が判明した:

**「師匠の承認で昇格」という設計が実用上破綻している。** コーディング中の師匠はプロジェクト推進に全神経を注いでおり、スキルのレビューに帯域を割けない。`forming で提示』『事後に取り消せる』は誰も見ず、無検証のまま永続化される。312/641 が承認痕跡なしという数字がそれを裏づける。

## 解の思想（師匠決定: 「機械が自動淘汰」）

師匠の指針「日本の職人の基本『見て盗め』」と、ray の `peer-agent-guidelines.md`（支配 vs 友）は同じ一本の思想:

- **支配のパラダイム**: 指示 → 盲従 → 外部遮断。承認で一件ずつ昇格を許可するのはこの名残。
- **友のパラダイム**: 意図提示 → 合意 → 境界内自律（Bounded Autonomy）。友は許可を出さない。
- **「見て盗め」＝参照ベースの自動淘汰**: AI が現場で参照して役立てた技が残り、使われない技は錆びて落ちる。承認ゲートを足すのは支配への逆行。

## 次スプリントへ（互いにほぼ独立・並列に割れる）

1. **参照の計装**（自動淘汰の心臓）: スキル参照の時刻・回数を記録する最小の仕組み。0 件のままでは淘汰は created_at 頼みの博打。
2. **参照ベース自動淘汰**: 計装が貯まったら、未参照 × 未確定（draft/forming）× 横断再現なし を機械で淘汰。闘値は設計判断（H1）。
3. **置き場の機械適用**: 固有名を剥くと中身が消える＝技術事実、は README 定義どおりプロジェクト固有へ機械移送。残すのは師匠の判断基準だけ。
