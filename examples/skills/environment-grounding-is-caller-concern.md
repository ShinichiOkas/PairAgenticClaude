エージェントを層状に構成するとき、**環境の文脈（OS・shell・cwd・ファイル一覧など）は行動ループ層の責務ではない。呼び出し側または外側の層が与える**。行動ループ層は「渡されたツールを回す」だけにして無汚染を保つ。

**Why:** 師匠の明示決定。行動ループ層の実タスク失敗（モデルが環境を知らず Unix コマンドを仮定・パスを幻覚）への対応として、環境プリアンブルは**呼び出し側とツールの責務**とし、暴走対策（ループ制御）は**さらに外側の層**の役割とした。「壊れていたのはループではなく、ツールと文脈だった」という切り分けと一体の決定。

**How to apply:**

- 行動ループ層に OS / cwd / shell の知識を埋め込まない。純粋に「ツールを実行する」だけにする
- 環境グラウンディングは呼び出し側（CLI / 上位層）が system プリアンブル等で注入する。ツールは自分の前提（例: PowerShell で実行される）を自身の説明文に明記する
- ループ制御（暴走の抑制・打ち切り・再計画）はさらに外側の層の責務。行動ループ層に持たせない
- **LLM に「実行物」を書かせる層（planner / specifier）にも env preamble を写す。** 行動する層だけに環境を与えると、計画層が環境に無いコマンド（`grep` / `ls` 等）を検査手順に書き、**正しい成果物が落ちる偽の不合格**を生む。実際に受入検証で発火した
- 前置するだけで中身には関知しない（opaque に扱う）方針は維持する
