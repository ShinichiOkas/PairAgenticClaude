実況・計測（ログ、所要時間、トークン数など）を足すとき、**層そのものには手を入れない**。呼び出し側が、既にスタックを組み立てている **DI 合成点**で層を proxy / wrapper に包み、観測を差し込む。

**Why:** 実行中の長い沈黙（LLM 推論・ツール実行）を可視化する要望に対し、**呼び出し側のファイル1つだけ**で実況を実現できた。最下層を層ラベル付きプロキシで、ツールをデコレータで包み、既存の合成点へ注入する。層は無変更のまま。

「環境グラウンディングは呼び出し側」（[[environment-grounding-is-caller-concern]]）と同じ非対称が**観測にも及ぶ** —— 状態も方針（上限・承認）も環境も観測も、すべて外側が与える。

**How to apply:**

- 観測を足したくなったら、まず「層を変えずに合成点で包めるか」を問う。層に print / log を埋め込まない（無状態・無汚染を保つ）
- 沈黙の正体（＝時間のかかる箇所）を合成点で特定する: モデル推論は最下層の proxy、ツール実行は tool の wrapper。**層ごとにラベルを変えると入れ子構造が見える**
- ラッパーは `functools.wraps` で `__name__`・docstring・シグネチャを保つ。ディスパッチや「関数 → スキーマ変換」が不変であることをテストで担保する
