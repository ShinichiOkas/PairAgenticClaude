実 embedding モデルや実 LLM を使う E2E 検証を、実データを汚さずに走らせる手順:

1. 一時ディレクトリを作り、データルートの環境変数（`*_BASE_DIR` 等）に設定する。実データディレクトリを汚さない
2. 実 config が要るなら**設定ファイルだけコピー**する。secrets はコピーしない（キー不要のローカルプロバイダーならこれで LLM も動く）
3. モデルキャッシュは**ディレクトリジャンクション**で共有する:

   ```
   cmd /c mklink /J <tmp>\models <実データルート>\models
   ```

   キャッシュディレクトリを指定するコードが既存キャッシュを再利用するので、**再ダウンロードが起きない**

4. 終了時は**ジャンクションを先に外してから**一時ディレクトリを削除する:

   ```
   rmdir <tmp>\models      # ジャンクションを外す（中身は消えない）
   ```

   **先に一時ディレクトリごと再帰削除すると、ジャンクションを辿って実モデルまで消える。順序厳守。**

**Why:** 重いモデルを使う E2E は「実データを使うと汚す」「一時環境だと数 GB を再ダウンロードする」の板挟みになる。ジャンクションは書き込み先を実キャッシュに向けるので、読み取り主体のキャッシュには安全に共有できる。実際にこの構成で、インデクサーから検索までを実データ非汚染で実機確認できた。

**How to apply:**

- 検証用フィクスチャは一時データルート側に手書きで仕込む。形式の契約は仕様書に従う
- LLM を呼ぶ E2E はコスト・時間が数十秒〜になることがある。件数を絞る
- **ジャンクション削除の検証を必ず入れる**: 削除後に実ディレクトリの中身が残っていることを確認する。この確認を省くと、消えたことに気づくのが数日後になる
- Unix なら `ln -s` ではなくバインドマウント／ハードリンクを検討する。シンボリックリンクは再帰削除の挙動が実装依存
