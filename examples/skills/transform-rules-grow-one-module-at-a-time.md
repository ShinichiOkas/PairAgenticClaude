上流コードを機械的に取り込む同期スクリプトの変換ルール（import 書き換え・副作用の無効化）は、**取り込み対象モジュールを1つずつ追加するたびに、発見された問題へ対応してルールを足す**。

```
1. allowlist にモジュールを1つ追加
2. 同期スクリプトを実行
3. 生成されたファイルを目視確認（副作用の無効化・import 書き換えが妥当か）
4. import を試行する
5. ImportError / IndentationError / NameError が出たら原因を特定 → スクリプトに新ルール追加
6. 再実行 → 通れば次のモジュールへ
7. 全体テスト pass を確認、実機スモークの維持を確認
```

**Why:** 実際の取り込みで追加されたルールは、いずれも**取り込みを実行して初めて発見された問題**への対応だった。ログハンドラの複数行ブロック、モジュールレベルの `mkdir` 副作用、`try` ブロックが空になる問題、未取り込みシンボルの呼び出し、Web フレームワークのレスポンス型を shim へリダイレクト —— 事前計画の段階では**どれも予測できなかった**。

「まず全ルールを設計してから一括取り込み」は、実行しないと見えない問題に対して機能しない。

**How to apply:**

- 取り込みは必ず1モジュール単位で回す。複数モジュールを一度に足すと、どのルールがどの問題に対応するか分からなくなる
- ルールはカテゴリ記号（A/B/C…）を付けて列挙しておく。新パターンが出たら適切なカテゴリに足す
- **過剰無効化に注意** — 関数内の副作用（実行時に必要な `mkdir` 等）まで消すと別の壊れ方をする。「行頭が空白でないものだけ無効化」のように条件を絞る
- 変換スクリプト自体の保存形式に注意する。PowerShell スクリプトを編集ツールで書き換えると BOM が落ちることがある。毎回復元処理を入れる
