師匠が思い付きを書き留める **inbox ファイル**（`IDEAS.md` 等）に未コミット変更があったら、**そのとき作業していた文脈と無関係でも、常に一緒にコミットして push する**。確認しなくてよい。

**Why:** inbox は師匠が「思いついたときに忘れないように書き込む」ファイル（師匠の明示宣言）。ローカルに置きっぱなしだと失われるので、**リモートに上がっていること自体が価値**。他の作業ファイルと違って「まだ途中だから触るな」という WIP ではなく、**書いた瞬間に確定している追記**。

実際に、無関係なコミットの際に inbox を「師匠の WIP」と見なして除外し、それが誤りだった。「自分の hunk だけコミットして WIP を守る」は**「師匠の未完成な作業を巻き込むな」**というルールであって、inbox ファイルには当てはまらない。

**判別軸は「師匠が触ったかどうか」ではなく「そのファイルが未完成状態を持ちうるか」。**

**How to apply:**

- コミット前の `git status` に inbox ファイルが出ていたら、自分の変更と一緒に `git add` する
- 主コミットと無関係なので、コミットメッセージ本文に一行添えるか、別コミットに分ける（どちらでもよい。分けるなら `chore(ideas): アイデアを追記`）
- 逆に **inbox だけ**が変更されている状態で放置しない。他の用事で push するときに必ず相乗りさせる
- **中身の選別（keep / promote / drop）は別作業**。コミット時に読んで判断しようとしない
