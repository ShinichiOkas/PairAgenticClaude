GUI を持つツールのβテスト期間中は、**「成果物を組み立てる」「動かす」はユーザー（師匠）の作業**とする。AI は成果物（ワークフロー定義・設定ファイル等）を事前に書いて提示せず、不具合報告とその成果物を受けて修正に回る。

**Why:** 師匠の明示宣言:

> 「ワークフローは僕がGUIで作る。作業自体をユーザーの立場でやることで不具合を発見するβテストを兼ねる。」

検証主体が人間でなければならないのは、AI が定義ファイルを直書きすると **GUI の DnD・接続・設定入力・実行経路で起きる問題を素通りしてしまう**ため。同じ定義でも GUI 経由で組み立てたときと挙動が違う可能性を潰す目的がある。

**How to apply:**
- AI はサンプル置き場（examples/ 等）に新規の成果物を**作らない**
- ユーザーが GUI で組んで保存した定義、または詰まった状態の定義を受け取ったら対応する
- 不具合報告を受けたら原因特定とコード修正に集中し、成果物の設計には踏み込まない
- ユーザーから「これを作って」と**明示的に**頼まれたときだけ例外
