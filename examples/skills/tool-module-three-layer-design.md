外部 API を叩くツール群（MCP ツール・エージェントのツール等）は、各モジュールを**3層**で書く。

| 層 | 例 | 性質 |
|---|---|---|
| **純粋整形関数** | `_format_*` | API 応答 → 文字列。副作用なし。モック無しで単体テストできる（CI 安全） |
| **I/O ヘルパー** | `_list_messages` 等 | 実 API 呼び出し。実機でのみ検証可能 |
| **register()** | — | ツールとして I/O ヘルパーを公開する |

テスト方針もこの層に従って分ける:

- **整形** — 純粋関数テストで回帰を守る。CI に載せる
- **I/O** — 実 API で検証する。CI には載せない
- **書き込み系** — 「作成 → 確認 → 削除」の自己完結で副作用を回収する。送信系は自分宛に送る

**Why:** 外部 API ツールは「モックすると何も検証できない」「実機だと CI に載らない」の板挟みになりやすい。応答の整形ロジック（実際にバグが出るのはここ）を純粋関数として切り出せば、その部分だけは決定的にテストできる。実機検証が必要な範囲を I/O ヘルパーに閉じ込めることで、検証コストの所在が明確になる。

**How to apply:**

- 新しいツールモジュールを書くときは、まず「この応答をどう文字列にするか」を純粋関数として書く。API 呼び出しと混ぜない
- 純粋関数テストは実応答のサンプルを固定データとして持つ。実機で1回取ってきて貼る
- 書き込み系ツールの実機検証は、必ず自分で後始末できる形にしてから走らせる
