GUI で要素（ノード・アイテム・ブロック等）をパレットから追加するとき、型（class_type）ごとに「毎回手で書きがちな値」をデフォルト設定として埋め、設定欄に即表示する。ユーザーは実値に書き換えるだけで動かせる。

```js
const DEFAULT_CONFIG_BY_TYPE = {
  LLMNode: { backend: "...", model: "..." },
  CSVProcessorNode: { skip_rows: 1, input_columns: ["text"], output_columns: ["result"] },
};
```

適用ルール:

- 「毎回ほぼ同じ値」になるパラメータがあれば必ずデフォルトに入れる
- 必須パラメータにサンプル値を入れる場合は、「実値に置き換える必要がある」ことが直感的に伝わる generic な名前にする（`["text"]`, `["result"]` 等）
- 機微情報（API キー等）はデフォルトに入れない

**Why:** βテストで師匠が GUI から組み立てる際、デフォルトのおかげで編集量が減りテストの回転が速くなった（振り返りで承認）。空の設定欄は「何を書けばいいか」の調査コストをユーザーに転嫁する。

**How to apply:**
- 設定を持つ要素型を GUI に追加するたび、その型のデフォルト辞書もセットで足す
- 関連: [[user-builds-workflows-ai-fixes]]（ユーザーが組み立てるからこそプリフィルが効く）
