同一プロダクト配下の姉妹アプリ（コンパニオン・サブアプリ）を並べるとき、**先発 → 後発の一方向の流用で終わらせない**。

流用対象はデザイントークンだけでなく、**先行アプリで確立したペイン構成・クラス語彙**（`.app-container` / `.panel` / `.panel-header` / `.drop-zone` / `.resizer` 等）も含む。そして横展開は**双方向**にする —— **後発アプリで出た改善は先発アプリにも戻す。**

**Why:** 実際に、後発アプリが先発のドロップゾーンと添付一覧を踏襲し、逆に先発アプリが後発の左ペイン構成を踏襲した。同じ UX を持つのに片方だけ古い体裁で残ると、**そちらだけが実機フィードバックを食い続ける** —— 同じ指摘を二度受けることになる。

**How to apply:**

- 姉妹アプリの UI を直したら、「**同じ体裁を持つ他のアプリはどれか**」を必ず数える。1つ直したら他も見る
- 共通化できるものは共通アセットへ寄せる。寄せられないなら、**横展開のタスクを WBS に立てる**（「あとで」にしない）
- **2例で定型化を確認してから**テンプレート化する。1例目は前例、2例目で定型として確定させる
- 定型は手順書として残す（配置・パッケージング・パス解決・ポート採番・ランチャー登録・GUI 流用・ドキュメント・テストの各点）
