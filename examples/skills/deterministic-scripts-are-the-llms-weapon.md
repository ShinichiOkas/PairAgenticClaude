## 師匠の宣言（原文 2026-10-27）

> そうだ！可能な限り作業は決定性のスクリプトにしろ。LLMの強さは柔軟性だがスクリプトの強さは再現性だ！柔軟な頭のLLMが強い武器としてスクリプトを使え！

（直前の宣言「技を身に着けろ、技が身に付けば荒くても乱れない」への続き。技＝スクリプト）

続けての宣言（原文 2026-10-27・全体のまとめ）:

> LLMの頭脳、技としてのスキル、武器としてのスクリプト、それを支えるCPU,GPU,Memory、すべてを使いこなせ

| 層 | 担うもの | 使い方 |
|---|---|---|
| LLM の頭脳 | 判断・組み立て・例外の扱い | 何をするか決め、スクリプトを書き、判定の要る所だけを考える |
| 技としての Skill | 型・規律・過去の失敗の教訓 | 着手前に引き、間違えたら即 Skill 候補にして持ち帰る |
| 武器としてのスクリプト | 再現性のある実行と検査 | 数える・突き合わせる・配る・写すを任せる |
| CPU・GPU・メモリ | それを回す計算資源 | 空いていたら仕事をくべる。GPU はローカル LLM の判定や埋め込みに使う |

## 何をスクリプトにするか

- **数える・突き合わせる**: 件数の照合、引用の原文照合、出力ファイルが担当数だけあるか、index と実ファイルの一致
- **分ける・配る**: 対象を担当グループに切る、既に割り当てたものを除く
- **写す・変換する**: 承認版 → 昇格版（フロントマターの付け替え）、結果表の集計
- **候補を絞る**: 類似度での重複候補の抽出（判定だけ LLM に回す）

**Why:** LLM の強みは柔軟性、スクリプトの強みは再現性。件数の数え間違いや目視の照合ミスは、決定性のスクリプトなら起きない。荒く速く回しても崩れないのは、この検査が下にあるから。

**How to apply:**

- 同じ手順を 2 回目にやろうとしたら、その場でスクリプトにする。使い捨てで書いたものも、効いたらリポジトリの道具に格上げする
- LLM（自分・サブエージェント）は「何をするか決める」「例外を判断する」「スクリプトを書く・直す」に使う。LLM に件数を数えさせたり、照合を目でさせたりしない
- スクリプトは書き込み前に下見（dry-run・件数・行数の一致）を出す形にする。荒く速く回しても崩れないのはこの検査があるから（[[forward-fastest-fall-dirty-never-stop]]）
- 判定が要る部分だけを LLM に渡す（例: 3-gram で候補を出す → ローカル LLM で同一か判定 → 結果をスクリプトで集計）
