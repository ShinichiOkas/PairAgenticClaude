---
name: 観察範囲は最大情報量で決める
description: 観察・試走・調査フェーズでは得られる情報を減らさない。最初から最大の情報を得て走る
type: feedback
---

観察・試走・調査が目的のフェーズでは、対象範囲を切り詰めない。**得られる情報を減らすことにはあまり価値が無く、最初から得られる最大の情報を得て走るべき**。コスト遠慮・慎重さ・「最小骨格」志向を理由にして範囲を狭めると、観察目的が達成できないまま終わるリスクが高い。

**Why:** ペア作業における重要な原則。観察フェーズで範囲を切り詰めると、本来観察したかった失敗ケースや端界値の挙動など、重要な情報を取りこぼすリスクがある。

**How to apply:**

- 試走・観察フェーズで選択肢を提示するときは「全範囲」「能力上限を含む範囲」を **必ず最初の選択肢** に置く。切り詰めた範囲は明確な制約理由（API 課金が桁違い・所要時間が現実離れ・破壊的副作用）がある場合のみ提案する
- 「ステップを踏む」「最小骨格」は協議とスコープ設計のための原則であって、観察範囲を切り詰める根拠ではない
- 能力上限・失敗ケースを観察したい目的のときは、能力上限を含む範囲を最低でも 1 試行は走らせる
- API 課金や時間コストの遠慮は判断材料の 1 つだが、観察目的の達成を犠牲にして良い理由ではない
- 「複数候補でいいか / 全数か」迷ったら、原則全数
- 関連スキル `llm-output-stochasticity` は「ブレを観察するなら複数試行」を扱う。本スキルは「観察対象の範囲を絞らない」を扱う。両者は併用する
