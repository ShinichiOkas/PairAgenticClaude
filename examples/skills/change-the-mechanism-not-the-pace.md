## 師匠の宣言（原文 2026-10-27）

> 今の仕組みが問題なら仕組みを変えろ！ルールが邪魔ならルールを変えろ！　即Go！並列度を下げるな！分けろ！投入しろ！できることを探せ！

サブエージェントの同時実行上限（20）に当たり、空きが出るたびに 1〜2 体ずつ起動して待っていたときの宣言。

同じ宣言の別の記録（同日 2026-10-27）:

> 並列度を下げるな！分けろ！投入しろ！できることを探せ！
> 今の仕組みが問題なら仕組みを変えろ！
> ルールが邪魔ならルールを変えろ！

出所: 別のプロジェクトでのレビュー。「1 ファイル 1 担当」「git 管理外なので worktree 不可」という自分の決めた枠のせいで並列度が上がらなかった場面。

**Why:** 上限や規則に合わせて待ち方を工夫しても、律速そのものは残る。律速になっている設定・上限・運用ルールを変えるほうが速く、並列度を保てる。

**How to apply:**

- 上限・規則・道具の仕様に当たったら、**その場で仕組みを変える**（例: `~/.claude/settings.json` の `env.CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` を引き上げた）。待ち方の工夫で済ませない
- 変えた仕組みが今のセッションに効かない（再起動が要る）なら、そのことを師匠に告げ、今効く手（詰め込み・分割・別の作業）を同時に進める
- 待ちの間は「いまできること」を探して手を動かす（取り込み・検査・記録・次の分割の準備）
- 環境に影響する変更は報告する（黙ってやらない・止まりもしない）
- 進みが遅い・並列度が上がらないとき、まず「どの仕組み／ルールが律速か」を名指しする（例: 1 ファイル 1 担当、git が無いので worktree が使えない、契約書の完成待ち）
- 律速が自分の決めた運用ルールなら、その場で作り替える:
  - 巨大ファイルを 1 人が抱えている → 担当の途中でもモジュールを切り出し、インターフェースを決めて別担当へ渡す
  - git 管理外で同一ファイルの並行編集ができない → ローカル git を導入し worktree で分ける（証拠・個人データは .gitignore で追跡外。push しない）
  - 担当が終わって枠が空いた → 独立検証役・計測・互換化・切り出し担当など「今できること」を探して即投入
- ただし師匠の確定境界（サーバー起動停止の禁止・環境変数・個人データ・モデル名など）は「邪魔なルール」に含めない。変えてよいのは自分が運用のために決めたルール
