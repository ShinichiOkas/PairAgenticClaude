---
name: LLM 出力の確率論的ブレを最初から織り込む
description: LLM の出力評価・テスト設計では、確率論的ブレの存在を最初から所与として、ブレに強い測定方式を選ぶ
type: feedback
---

LLM を被測定対象とするテスト設計・評価設計では、出力の確率論的ブレを最初から所与とし、ブレの影響を受けにくい判定方法を採用する。出してから「ブレるから直そう」とするのではなく、最初から「ブレても判定できる」形で出す。

**Why:** 師匠の明示的な指摘（2026-05-08 振り返り）。「LLM の出力は確率論的ぶれを含むことがわかっているのだから最初からブレの影響を受けない測定方法を考えられるとよりよかった」。私が L0 課題を最初テキストの厳密一致で設計したことへの修正。

**How to apply:**

- 採点シグナルは「テスト通過 / exit code / ファイル存在 / JSON のキー一致」のように、ブレた表現でも同じ結論に収束する形にする
- 「テキストの厳密一致」「特定の文字列が含まれる」「順序ありリスト一致」は避ける。同じ意図でも揺らぐ
- read-only 質問のような自然言語応答系でも、可能なら機械可読形式（JSON / 既定スキーマ）への書き出しを要求し、その内容を構造的に検証する
- LLM 出力を直接パースするより、LLM に「ファイルに書け」と命じてファイルを検証する方が安定する
- 評価ハーネスの集計指標として `success_rate`（N 試行中 M 回成功）を最初から持つ。1試行で成否を決めない
- 「最初の設計でブレるかどうか分からない」と感じたら、それは「ブレる」と思って組むべき合図
