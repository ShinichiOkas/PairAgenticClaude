同じリポジトリに複数の Python 環境（`venv/` と `.venv/` 等）が同居していると、**実運用でない方を先に見つけて誤診断する**。

正は**起動スクリプトが activate している環境**。テスト・E2E・スクリプト実行はそこで行う。ツールが自動生成した環境（`uv run` / `uv sync` 等が作る `.venv`）は、依存やパッケージ登録が古く実運用と乖離していることがある。

**Why:** バグ修正中に自動生成された方の環境を先に見つけて使い、「依存の同期漏れで別コンポーネントの機能も動作しない」という**誤診断を一度書いてしまった**。実開発環境には導入済みだった。**環境の取り違えは検証結果ごと信用を失わせる。**

**How to apply:**

- Python を実行する前に、まず**起動スクリプト（`launch_*.bat` / `run.sh` 等）がどの環境を activate しているか**を読む。それが正
- 環境起因の不具合を記録する前に「その環境は本当に実運用の環境か」を確認する。記録に残った誤診断は後で他人（と未来の自分）を誤導する
- 事故で生成された環境は削除する。再出現したら自動生成コマンドを疑う
- 同じ判断は Python に限らない。node_modules・コンテナ・PATH 上の実行ファイルでも同型の取り違えが起きる
