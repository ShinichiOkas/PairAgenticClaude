並列作業中は、**完了かつ検証済みの担当のファイルだけ**をコミットする。作業中の担当のファイルは `git add` しない・退避しない・戻さない。フックの要求とぶつかる場合は、「まだ作業中の担当がいるためクリーンにできない」事実を**師匠に告げる**（フックを満たすために巻き込まない）。

**Why:** 実際に、セッション途中で git を導入したところ、停止フックが「作業ツリーをクリーンに」と要求した。しかしそのとき背景のサブエージェントが同じツリーに書き込み中で、全部をコミットすると**未完成のファイルを確定させる**ことになる状況だった。別のスプリントの並列改修でも同じ運用が有効だった。

**How to apply:**

- コミット前に、各担当の状態（作業中／完了／検証済み）と所有ファイルを対応づけ、対象を絞って `git add <path>`。
- コミット後に `git status --short` で残りが作業中担当のファイルだけであることを確認し、報告に書く。
- 担当ごとのファイル所有を最初に決めておく（[[work-must-be-split-across-subagents]]）と、この切り分けが楽になる。
