各層には、**その層だけを使う最小の CLI チャット**を用意する（`l0_chat.py` / `l1_chat.py` …）。師匠がその層を**実際に触って**動きと質感を確かめられる窓口。

**Why:** 師匠の明示宣言 —— 層の完成後に「僕が実際に触ってみられるように CLI のチャットアプリを作ってよ。各層ごと最もシンプルな実装で」→「確定ルールとして登録」。師匠は**動く具体物のシンプルさ**で質感を確かめる。早く薄い実物を触れる形で出すことを重視する。

仕様書やテスト結果では伝わらない情報（応答の速さ・出力の粒度・失敗の出方）が、触った瞬間に伝わる。

**How to apply:**

- 層を完成させたら、対になる最小 CLI を用意する。その層**だけ**を使い、最もシンプルに
- CLI は薄いドライバに徹する。会話履歴などの状態は CLI 側が持ち、層は無状態を保つ。層のエラー契約はそのまま見せる（CLI で握り潰さない）
- Windows コンソールでも落ちないよう入出力は UTF-8 に揃える（cp932 で em-dash 等が落ちる既知の穴 → [[windows-debug-output-cp932-safe]]）
- 既定モデル等は引数で上書きできるようにする
