**割り付けは課題を生む。どこにも割り付かない要素はそれ自体が課題であり、実装先（プラットフォーム）へ割り付ければ新しい課題が出る。それを二週目として同じ決定ループで解く。**

## なぜこの体系で要るか

論理構造だけがあって実装先が無ければ、**誰も作らない部品かもしれない**。実装部品だけがあって論理上の役割が無ければ、何のためにあるか分からない。割り付けの図は、その抜けを見つける表現である（§5.6）。
実装先に依存しないモデル（PIM）で考えたことを、実装先の制約に従ったモデル（PSM）へ割り付けると、新たな課題が出る（§17）。

デジタル時計の例（§17、pptx Slide37〜38）: 普通のデジタル時計の構造をプラットフォームとして、目覚ましの要素を割り付ける。
→ 「この IF はどこから引っ張る？」「電源は共有？」「UI は別の表示装置か、共有するか？」が新しい課題になる。
**PF 構造は PF 制約なので変えてはいけない。**

## How to apply

- **割り付けは連鎖して辿る。** 要求 → 論理コンポーネント → ソフトウェアモジュール → CPU（炊飯器: 制御 → 温度の計測 → マイコン）。一対多・多対多でもよい
- **割り付け表を作り、割り付け先の無い要素を「未割り付け」の課題として起票する。** 「作らない」と決めるか、先を決めるかを書く
- **変えてはならない PF 構造は、案を出す前に制約として書く。** 制約に反する案は最初から候補から外す。システム外の電源の上限も同じ扱い（→ 構造制約の書き方）
- **割り付けで出た課題は、一周目と同じ手順（三案・欠点の由来・検証・決断）で解く。** 新しい品質特性が出たら優先度を決め直す（→ 視点の異なる三案、重みのラベル付け）
- ⚠ **手法には PIM／PSM の区別は無い**（14-textbook-correspondence.md M6・Q7）。教科書の語として使い、割り付けビューの連鎖で表す
